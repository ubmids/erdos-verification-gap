# The verification gap in AI-assisted Erdős problem solving: dataset and code

This is the data and analysis code for S. Olagoke, *Faster Than They Can Be Checked: Measuring the verification gap in AI-assisted solutions to Erdős problems* (2026).

Data were collected on **25 September 2026** from public sources only.

## Contents

| Path | What it is |
|---|---|
| `data/claims.csv` | All 251 proof claims on erdosproblems.com, 14 Jul – 24 Sep 2026, one row per claim, with hand-coded verdicts (see `CODEBOOK.md`) |
| `data/status_changes.json` | Every status change of every problem in the git history of `teorth/erdosproblems` (1,366 commits, 2,614 changes) |
| `data/ledger_final.json`, `data/ledger_events.json` | Tao's "AI contributions to Erdős problems" ledger: final table and every outcome change across its edit history (frozen 30 Jun 2026) |
| `data/problems_pages.json` | Per-problem page snapshot: status label, comment count, proof-claim count |
| `code/` | Collection (`collect.py`), timelines (`timeline.py`, `ledger.py`), per-claim derivation (`analyze_claims.py`), all numbers and figures (`analysis.py`) |
| `results.json`, `figures/` | Every number and figure in the paper |

## Privacy

Everything here comes from public posts. The rule we followed is simple: **authorship stays visible, and who judged whom stays pseudonymous.**
- **Reviewers.** Reviewer and verdict-giver identities are replaced by stable pseudonyms (`U` + 6 hex characters), in `claims.csv` and in `results.json`. Quotes are at most 30 words, with any username redacted, and full comment texts are left out.
- **Claimants** are also pseudonymised in the `claimant` column. However, `proof_url` and `lean_url` link to claimants' own public repositories, so they identify claimants as the authors of their published work. We keep them, because citing someone's public proof is attribution.
- **Ledger files** reproduce the public ledger's own credits, which name some human collaborators on results, unchanged.
- **Threads.** Each claim links to its public thread (`thread_url`), so anyone can check a code against the source.

## Reproducing

- `code/collect.py` refetches the public pages politely, at one request every 1.2 s. The live forum changes, so a rerun will reflect its state on that date.
- `analysis.py` was run on the full, non-pseudonymised collection; its inputs are regenerated by `collect.py` and `analyze_claims.py`. Every claim-level statistic in the paper can also be recomputed from `data/claims.csv` alone.
- The hand-coded verdicts are not regenerated by code. Their rules are in `CODEBOOK.md`.
